# pixelkit

코드로 그리고, 뽑아서 보고, 가장 나쁜 곳을 고치는 과정을 반복합니다. 한 번에 그린 그림은 대개 평범하고, 보고 고친 그림이 좋아집니다. 뽑은 견본을 열어 보지 않고 다음 단계로 넘어가지 않습니다.

구성과 함수 목록은 `pixelkit/README.md`에 있습니다. 이 문서는 절차와 판단 기준만 다룹니다.

## 시작 전 확인

저장소 최상위에서 아래 두 명령이 동작하는지 확인합니다.

```sh
node pixelkit/tools/render.mjs icon/gear     # pixelkit/records/pick.png 생성
node pixelkit/tools/check.mjs icon/gear      # ok
```

생성된 PNG를 이미지 읽기 도구로 엽니다. 앞으로 모든 그림은 이 방법으로 확인합니다.

## 절차

### 1. 한 줄로 말하기

무엇인지, 크기, 색, 보는 방향, 어디에 놓이는지를 한 문장으로 적습니다. 이 문장을 쓰지 못하면 아직 그릴 준비가 되지 않은 것입니다.

- 캐릭터 동작: "우산을 쓰고 걷기. 2프레임, 우산은 발걸음에 맞춰 1px 오르내리고, 손잡이는 얼굴 앞에서 쥔다."
- 타일: "밝은 원목 바닥 16x16. 긴 널 네 줄, 이음은 한 줄 건너 하나, 결은 널 가운데에만."
- 아이콘: "종 16x16. 노란 몸통에 왼쪽 위 밝은 면, 아래 붉은 추, 외곽선 1px."

### 2. 기존 것 참고

같은 종류의 기존 그림을 먼저 뽑아서 봅니다. 새 그림은 그 옆에 놓였을 때 같은 세계의 것으로 보여야 합니다.

```sh
node pixelkit/tools/render.mjs --list
node pixelkit/tools/render.mjs char/sky char/sky-jump --zoom 6
node pixelkit/tools/render.mjs floor wall
```

그다음 가장 가까운 그림의 코드를 읽고 방식을 가져옵니다. 캐릭터는 `char/draw.js`의 `front`와 `side`, 타일은 `tile/floor.js`, 아이콘은 `ui/icons.js`가 기준입니다. 앱이 지금 쓰는 그림과 맞춰야 할 때는 `loadPNG`로 `assets/pixel/town/*.png`를 읽어 견본에 나란히 놓고 비교합니다.

특정 게임이나 서비스의 캐릭터, 그림, 로고는 따라 그리지 않습니다. 흔한 소재(우산, 종, 톱니바퀴)를 우리 화풍으로 새로 그립니다.

### 3. 초안

종류별로 손댈 곳은 다음과 같습니다.

| 만드는 것 | 손댈 곳 |
|---|---|
| 캐릭터 색, 머리 모양, 옷 종류 | `char/parts.js`의 표에 줄 추가. 옷 무늬는 `char/draw.js`의 `tops` |
| 캐릭터 동작 | `char/poses.js`의 `POSES`에 자세, `ACTIONS`에 프레임 순서. 새 팔 모양은 `char/draw.js`의 `front`와 `side` 양쪽에 추가 |
| 바닥, 벽 | `tile/floor.js`의 `FLOORS`, `tile/wall.js`의 `WALLS`에 함수 추가 |
| 하늘, 건물 조각 | `tile/sky.js`, `tile/building.js` |
| 아이콘 | `ui/icons.js`의 `ICONS`에 함수 추가. 외곽선은 자동으로 그려지므로 가장자리 1px을 비워 둡니다. |
| 패널, 버튼 | `ui/panel.js`의 `PANELS`, `ui/button.js` |
| 도크 거리의 건물, 보도, 가로등 | `tile/street.js`. 건물 배치는 `ROW` 표, 불이 켜지는 곳은 `painter`의 `glass`, `lamp`, `spill`로만 그립니다. |

마지막으로 `catalog.js`에 항목을 추가하고 규격(`spec`)을 적습니다. 규격을 적어야 검사 대상이 됩니다.

지킬 것은 다음과 같습니다.

- 색은 `core/color.js`의 `RAMP`에서 고르거나 `shade`와 `tint`로 만듭니다. 검정과 흰색을 섞어 명암을 만들지 않습니다.
- 한 그림에 쓰는 한 색상의 단계는 3개(어둠, 기본, 밝음)를 넘기지 않습니다.
- 빛은 왼쪽 위에서 옵니다. 밝은 줄은 위와 왼쪽에, 어두운 줄은 아래와 오른쪽에 놓습니다.
- 무작위가 필요하면 `new Rng(seed)`나 `rand`를 씁니다. 씨앗 없는 난수는 검사에서 실패합니다.
- 타일에 씨앗으로 찍는 무늬는 가장자리를 넘어가면 반대편에서 이어지게 합니다(`tile/floor.js`의 `dash` 참고).
- 방향이 열려 있으면 서로 다른 초안을 2~3개 만들어 한 장에 뽑아 놓고 고릅니다.

### 4. 뽑아서 보고, 가장 나쁜 곳 하나 고치기 (3회 이상)

```sh
node pixelkit/tools/render.mjs <id들> --zoom 6
```

1. 견본 PNG를 엽니다.
2. 까다로운 픽셀 아티스트의 눈으로 보고, 가장 나쁜 곳 하나를 고릅니다. 아래 처방표를 참고합니다.
3. 그 하나만 고치고 다시 뽑습니다.

이 과정을 최소 3회 반복합니다. 매회 다음 세 가지 배율을 확인합니다.

- 큰 배율(6~8배): 점 하나하나의 위치를 확인합니다.
- 실제 배율(1~2배): 한눈에 무엇인지 읽히는지 확인합니다. `icon/all-x1`처럼 작게 모아 놓은 항목이 이 용도입니다.
- 놓일 자리: 타일은 `tiled()`로 반복한 모습을, 캐릭터와 UI는 `scene/office`, `scene/street`처럼 다른 그림과 함께 놓인 모습을 확인합니다.

캐릭터 동작은 프레임을 번갈아 보며 움직임이 읽히는지 확인하고, 세 방향 줄을 모두 확인합니다.

### 5. 검사

```sh
node pixelkit/tools/check.mjs <id들>
node pixelkit/tools/check.mjs            # 끝내기 전에 전체
node --test test/pixelkit.test.mjs
```

실패는 모두 고칩니다. 주의(warn)도 읽고, 의도한 것이면 규격의 예산(`maxLone`)을 근거와 함께 조정하고, 의도하지 않은 것이면 그림을 고칩니다. 검사를 통과시키려고 규격을 느슨하게 바꾸지 않습니다.

### 6. 마무리

`node pixelkit/tools/render.mjs`로 묶음별 견본을 다시 만들고, 캐릭터나 도크 거리 그림을 고쳤다면 `node pixelkit/tools/export-app.mjs`로 앱이 읽는 파일(`assets/pixel/town/`)도 다시 내보냅니다. 내보낸 파일이 코드와 다르면 테스트가 실패합니다. 그리고 고르지 않은 초안은 지웁니다. 다른 곳에서 가져온 코드가 있으면 `NOTICE.md`에 출처와 저작권 표기를 추가합니다.

## 증상별 처방표

| 보이는 증상 | 처방 |
|---|---|
| 실제 배율에서 뭉개져 무엇인지 모르겠다 | 색 수를 줄이고, 실루엣을 먼저 맞춘다. 모양을 키우고 세부를 뺀다. |
| 점이 흩뿌려진 것처럼 지저분하다 | 외톨이 점을 2px 이상으로 묶거나 없앤다. 선 위에 디더를 겹치지 않는다. |
| 밋밋하고 평평하다 | 왼쪽 위에 밝은 단계, 오른쪽 아래에 어두운 단계를 한 줄씩 넣는다. |
| 탁하고 칙칙하다 | 명암을 검정 대신 `shade`(차가운 쪽)와 `tint`(따뜻한 쪽)로 만든다. 채도 낮은 중간색을 줄인다. |
| 기존 그림 옆에서 혼자 튄다 | 외곽선을 `INK`로 통일하고, 대비를 낮추고, `RAMP`의 색으로 바꾼다. |
| 부드러운 번짐이 있어 픽셀 그림 같지 않다 | 반투명을 쓰지 않는다. 옅어지는 표현은 `rect(..., a)`나 `bands`의 디더로 바꾼다. |
| 타일을 이어 붙이면 줄이 보인다 | `seamReport`의 `seam`과 `inner`를 본다. 가장자리에 걸친 무늬를 반대편까지 이어 그리거나, 가장자리의 밝은 줄과 어두운 줄이 맞닿지 않게 한다. |
| 타일이 벽돌처럼, 또는 격자처럼 반복되어 보인다 | 이음과 무늬의 간격을 타일 크기와 어긋나게 하고, 한 타일 안의 이음 수를 줄인다. |
| 캐릭터의 팔이나 소품이 코나 뿔처럼 보인다 | 얼굴 옆에서 끝나지 않게 더 길게 뻗거나, 옷 색 점을 2개 이상 이어서 팔임을 알린다. |
| 동작이 움직이는 것처럼 보이지 않는다 | 프레임 사이에 실루엣이 바뀌게 한다. 몸을 1~2px 올리고 내리며, 팔과 다리를 반대로 움직인다. |
| 그림이 프레임 가장자리에서 잘린다 | 검사의 "cut off" 위치를 본다. 그림을 1px 줄이거나 안쪽으로 옮겨 외곽선 자리를 남긴다. |
| 소품이 몸에 묻혀 안 보인다 | 소품을 몸통보다 넓게 그리고, 옷과 밝기가 다른 색을 쓴다. |
| 9-slice로 늘리니 줄무늬가 생긴다 | 반복되는 가운데 구간에 선이 들어가지 않게 원본을 고치거나 inset을 키운다. |
| 아이콘이 어두운 배경에서 사라진다 | `icon/all-dark` 견본을 본다. 안쪽 색을 한 단계 밝게 하고 외곽선에 닿는 면을 넓힌다. |
| 도크에서 캐릭터 머리 위가 잘린다 | 도크는 위 4px이 잘린 16x28 창으로 보여 준다. 머리 위 소품을 y 4 아래로 내리고 `dock-street/chars-*` 견본으로 확인한다. |
| 밤 그림과 낮 그림이 불빛 밖에서도 다르다 | 불이 켜지는 부분을 `painter`를 거치지 않고 직접 그렸는지 확인한다. |
| 뽑을 때마다 그림이 달라진다 | 씨앗 없는 난수나 시간 값을 썼는지 확인하고 `Rng`로 바꾼다. |

## 품질 기준

- 실제 배율에서 무엇인지 한눈에 읽힌다.
- 기존 그림(`assets/pixel/town`)과 나란히 놓았을 때 같은 세계의 것으로 보인다.
- 같은 입력이면 항상 같은 그림이 나온다.
- `check.mjs`가 실패와 주의 없이 통과한다.
- 견본을 3회 이상 직접 보고 고쳤다.
