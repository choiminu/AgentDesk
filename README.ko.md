# AgentDesk

AI 코딩 에이전트를 위한 픽셀 아트 사무실입니다. AgentDesk는 macOS·Linux·Windows에서 동작하는 데스크톱 위젯으로, Claude Code·Codex CLI·Gemini CLI 세션을 실시간으로 지켜보고(일반 터미널이든 [Orca](https://github.com/stablyai/orca) 안이든) 각 에이전트가 무엇을 하는지 대시보드와 책상에 앉은 캐릭터로 보여 줍니다.

*이전 이름은 "Orca Widget"입니다. Orca는 선택 사항이며, 지원하는 에이전트 CLI 하나만 있으면 동작합니다.*

**지원 에이전트:** Claude Code, Codex CLI, Gemini CLI. 세 CLI 모두 자체 훅 체계로 세션 상태를 받습니다. 다만 위젯 승인·가드레일·위임·한도 막대 같은 기능은 Claude Code에서만 동작합니다. 자세한 내용은 [에이전트별 지원 범위](#에이전트별-지원-범위)를 보세요.

## 기능

- **실시간 대시보드**: 터미널·tmux·Orca에서 실행 중인 에이전트 세션의 실제 상태(작업 중 / 입력 대기 / 선택 필요 / 완료 / 오류)를 보여 줍니다. 정확 감지를 켜면 훅 이벤트로 판정하고, 훅이 없는 Claude Code 세션은 터미널 화면을 읽어 판정합니다.
- **픽셀 오피스**: 최근 세션이 캐릭터로 표시됩니다. 작업 중인 에이전트는 사용하는 도구에 따라 배정된 스테이션(개발 / 조사 / 실행·테스트 / 문서화) 책상에서 도구 태그와 컨텍스트 게이지를 달고 일합니다. 서브에이전트는 부모 옆에 나타나고, 쉬는 에이전트는 휴게실 소파에 앉습니다. 벽의 화이트보드가 현황을 요약합니다.
- **도크 모드**: 위젯을 화면 아래 가장자리의 얇은 띠로 바꿉니다. 아래 [도크 모드](#도크-모드) 절을 보세요.
- **PM 팀**: 에이전트를 PM 자리에 드래그해 팀을 만들고 다른 에이전트를 팀원으로 끌어 넣습니다. PM에게 목표를 주면 팀 브리프와 업무 분배안을 만들고, 승인하면 각 팀원이 브리프와 자기 태스크를 받습니다. 보고는 PM에게 자동으로 돌아갑니다.
- **선택 필요 알림**: 권한 승인이나 질문처럼 사람이 답해야 할 때만 알림·토스트·트레이 배지·알림음이 뜹니다.
- **재알림·위임 세션 알림**: 승인 대기와 응답 없음이 이어지면 설정한 간격(기본 15분, 세션당 한 시간에 최대 2번)마다 다시 알립니다. 나에게 위임된 팀원 세션은 입력 가능·승인 필요·완료·오류·응답 없음으로 바뀔 때 한 번씩 알립니다. 간격과 응답 없음 기준(기본 30분)은 ⚙ 설정 → 감지와 알림에서 바꿉니다.
- **검토 대기열(📥)**: 헤더의 📥 N을 누르면 권한 요청, Jira 보고 대기, 변경 보기, 받은 메모, 팀원 등록 요청, 위임받은 세션의 입력 가능·승인 필요, 한도 경고, 응답 없음 세션을 급한 순으로 한 목록에서 봅니다. 메모 [세션에 전달]·팀원 [추가]·권한 [거부]는 목록에서 바로 처리합니다. 대기열은 알림을 따로 띄우지 않으며, 종류별 포함 여부는 ⚙ 설정 → 감지와 알림 → **대기열에 포함할 항목**에서 정합니다.
- **채팅 패널**: 캐릭터나 카드를 클릭하면 에이전트 화면을 읽고 메시지를 보낼 수 있습니다. 더블클릭하면 그 터미널로 전환합니다.
- **팀 공유**: 같은 사무실 망의 팀원 세션을 팀 탭과 픽셀 사무실에서 봅니다. 초대 코드로 팀을 만들거나 합류하고, 같은 파일을 동시에 고치는 충돌을 알려 주며, 팀원 세션에 메모를 남기거나 세션을 위임할 수 있습니다. [팀 공유](#팀-공유) 절과 [팀 공유 가이드](docs/TEAM-GUIDE.md)를 보세요.
- **Jira 연동**: Atlassian OAuth로 로그인해 칸반 보드로 티켓을 보고, 티켓을 새 워크트리나 기존 세션에 배치하고, 세션의 REPORT를 Jira 댓글 초안으로 만듭니다. [Jira 연동](#jira-연동) 절을 보세요.
- **위젯에서 권한 승인**(Claude Code): Claude Code의 도구 권한 요청을 위젯 카드에서 [허용]·[거부]합니다. 기본은 꺼져 있습니다.
- **가드레일**(Claude Code): Bash 명령과 파일 편집 대상 경로를 실행 직전에 위험 규칙과 맞춰 보고, 경고하거나 막습니다. 기본은 꺼져 있습니다.
- **변경 보기와 리뷰 코멘트**: 세션 작업 폴더의 git 변경을 카드 안에서 보고, 줄마다 코멘트를 남겨 세션에 한 번에 보냅니다.
- **세션 타임라인**: 세션의 훅 이벤트를 시간축으로 보여 줍니다(도구 호출, 서브에이전트, 승인 대기, 사용자 대기).
- **한도 소진 예측과 티켓별 비용**: 한도 막대 아래에 소진 예상 시각을 표시하고, Jira에서 배치한 티켓마다 추정 비용을 합산합니다.
- **앱 내 업데이트**: 하루에 한 번 GitHub 릴리스를 확인하고, ⚙ 설정의 "업데이트" 행에서 [받기]로 이 기기용 설치 파일을 내려받습니다.
- **외부로 나가는 글 마스킹**: Jira 댓글·Slack 회신·팀 공유 데이터는 보내기 직전에 비밀 패턴을 `[MASKED]`로 바꿉니다. 테스트 카드번호·이메일도 가려지며, 댓글 초안에 "비밀 패턴 N곳을 [MASKED]로 바꿨습니다"가 표시됩니다.
- **슬랙 창구·아침 브리핑·세션 노트**: Slack에서 받은 요청을 세션에 넘기고 REPORT를 스레드에 회신하는 창구, 매일 아침 브리핑, 세션 노트(recall)가 있습니다. 이 기능들은 소스 체크아웃(`recall/`)이 있는 PC에서만 켜집니다. [세션 노트 (recall)](#세션-노트-recall)를 보세요.
- **영어·한국어 UI**: 기본은 영어이며 ⚙ 설정에서 바꿉니다.
- **타이머**: 뽀모도로 타이머 페이지가 있고, 도크 띠에서도 남은 시간을 보여 줍니다.

### 도크 모드

헤더의 ▭ 버튼이나 ⌘⇧D(Windows·Linux: Ctrl+Shift+D)로 위젯을 화면 아래 가장자리에 붙는 얇은 가로 띠로 바꿉니다.

- **타일**: 세션마다 픽셀 캐릭터 타일이 하나씩 있습니다. 캐릭터 아래에 세션 이름이, 발밑에 상태 링·대기열 숫자 배지·서브에이전트 점이 붙습니다. 띠에는 팀원 세션(팀 공유 시, 🔑는 위임받은 세션), 📥 대기열, 한도 막대도 함께 있습니다.
- **상태 표시**: 작업 중이면 캐릭터가 움직이고 현재 도구($·✎·≡ 등)와 최근 1분 도구 호출 막대가 붙습니다. 입력 대기는 초록 링, 승인 필요는 노란 ! 배지, 오류는 빨간 테두리입니다. 상태가 이어진 시간(3m, 1h 등)이 오른쪽 위에 붙고, 입력 대기 10분·작업 중 30분을 넘기면 노란색이 됩니다.
- **터미널 창**: 타일에 마우스를 0.2초 올리면 띠 위에 그 세션의 터미널 창이 열립니다. 화면 200줄을 마스킹해 1초마다 갱신하고, 입력 대기일 때 아래 입력 줄로 메시지를 보낼 수 있습니다. 권한 요청이 뜨면 입력 줄 자리에 [허용][거부]가 나오고, [중단](확인 후)·[터미널로] 버튼도 있습니다.
- **선택 말풍선**: 세션이 선택을 기다리면(권한 요청, AskUserQuestion, 번호 선택지) 타일 위에 질문과 선택지 버튼이 뜹니다. 버튼은 0.8초 뒤에 눌리고, 가드레일이 위험하다고 판단한 프롬프트는 "No" 쪽만 누를 수 있습니다. 말풍선이 하나만 떠 있으면 숫자키 1~9로도 고릅니다.
- **완료 말풍선**: 내 세션이 작업을 마치면 마지막 응답의 첫 줄(마스킹, 80자)을 8초 동안 띄웁니다.
- **[허용] 범위**: 도크의 [허용]은 한 줄로 다 보이는 Bash 명령과 짧은 요청에만 뜹니다. 파일 편집이나 잘린 요청은 [패널에서 보기]로 패널에서 확인합니다.
- **클릭과 단축키**: 타일을 누르면 그 세션의 실제 터미널로 전환하고, 더블클릭하면 패널의 그 카드로 갑니다. ⌘1~⌘9(Windows·Linux: Ctrl+1~9)는 왼쪽부터 n번째 내 타일의 터미널로 전환합니다. 이 키는 위젯 창에 포커스가 있을 때 동작합니다. ⚙ 설정 → 기타 → **전역 단축키**를 켜면(다른 앱의 단축키와 겹칠 수 있어 기본은 꺼짐) 다른 앱을 쓰는 중에도 ⌘⇧D로 도크를 전환하고 ⌘⇧A(Windows·Linux: Ctrl+Shift+A)로 가장 급한 승인 요청을 엽니다.
- **방해 금지(🔕)**: 켜면 말풍선·알림·데스크톱 알림이 멈추고 타일 색과 ! 배지만 남습니다.
- **순서와 고정**: 내 타일을 끌어 다른 타일 사이에 놓으면 순서가 저장되고 그 세션은 고정됩니다. 우클릭하거나 길게 누르면 "고정 해제" 메뉴가 나옵니다.
- **새 세션(＋)**: 내 타일 끝의 ＋를 누르면 Orca 저장소와 이름을 골라 Claude 워크트리 세션을 만듭니다.
- **끌어다 놓기**: 다른 앱의 텍스트·URL·파일을 입력 대기 중인 내 타일에 놓으면 마스킹된 미리보기를 확인한 뒤 [보내기]로 그 세션에 보냅니다. 파일은 경로만 보내고, `/`·`!`·`#`로 시작하는 텍스트는 보내지 않습니다.
- **위치**: 끌어 둔 띠 위치는 모니터마다 따로 기억합니다. "마우스가 멀어지면 숨기기"를 켜면 마우스가 떠나고 2초 뒤 띠가 가장자리로 밀려 8px만 보입니다.
- **설정**: ⚙ 설정 → 표시에서 시작 시 도크 모드, 도크 크기(작게·보통·크게), 숨기기, 완료 말풍선, 도크 애니메이션, 호버 시 터미널 창 열기, 흐림 정도(기본은 흐리지 않음)를 고릅니다.

## 에이전트별 지원 범위

세 CLI의 세션은 모두 대시보드와 오피스에 나타나지만, 기능마다 지원 범위가 다릅니다.

| 기능 | Claude Code | Codex CLI | Gemini CLI |
|---|---|---|---|
| 상태(훅) | 예 (18개 이벤트) | 예 (11개 이벤트, `PermissionRequest` 포함) | 예 (8개 이벤트). 권한 대기는 `Notification`(`ToolPermission`)으로만 감지 |
| 화면 기반 상태 판정(훅이 없을 때) | 예 | 아니요(Claude Code TUI 문구 기준) | 아니요(Claude Code TUI 문구 기준) |
| 위젯에서 권한 승인 | 예 (훅. Windows는 named pipe, 실기기 미검증) | 아니요 | 아니요 |
| 가드레일 | 예 (훅. Windows는 named pipe, 실기기 미검증) | 아니요 | 아니요 |
| 선택 말풍선(도크) | 예 | 아니요(Claude Code TUI 문구 기준) | 아니요(Claude Code TUI 문구 기준) |
| 팀원에게 위임 | 예 | 아니요 | 아니요 |
| 한도 막대·소진 예측 | 예 (Orca 사용 시) | 아니요 | 아니요 |
| 티켓별 비용 | 예 | 아니요 | 아니요 |
| 트랜스크립트 메타(제목·마지막 응답·컨텍스트) | 예 | 예 | 부분: 컨텍스트 창을 모델과 관계없이 1M으로 계산 |
| 진행 요약 한 줄 | 예 | 부분: 요약에 `claude` CLI가 필요 | 부분: 요약에 `claude` CLI가 필요 |
| 종료 세션 다시 열기 | `claude --resume` | `codex resume` | `gemini --resume` |

OpenCode 세션은 프로세스 목록에서 감지되어 라벨만 표시됩니다. 훅과 다시 열기는 지원하지 않습니다.

## 빠른 시작

요구 사항: macOS·Linux·Windows, 에이전트 CLI 하나 이상(Claude Code, Codex CLI 또는 Gemini CLI). 소스에서 실행하려면 Node.js 18 이상이 필요합니다. [Orca](https://github.com/stablyai/orca) 1.4 이상은 선택 사항이며, 없으면 훅 전용 모드(훅 + 메시지 전송용 [tmux](https://github.com/tmux/tmux))로 동작합니다.

```bash
git clone https://github.com/choiminu/AgentDesk.git
cd AgentDesk
npm install
npm start
```

설치 파일은 [GitHub 릴리스](https://github.com/choiminu/AgentDesk/releases)에 첨부됩니다(macOS DMG Apple Silicon·Intel, Linux AppImage·.deb, Windows 설치 프로그램·포터블 .exe). 직접 빌드하려면 `npm run dist`(macOS), `npm run dist:linux`, `npm run dist:win`을 사용합니다.

### 플랫폼별 지원

| 플랫폼 | 세션 상태(훅) | 채팅·지시·인터럽트 | 터미널 전환 | 위젯 승인·가드레일 | 종료 세션 다시 열기 |
|---|---|---|---|---|---|
| macOS | ✓ | Orca, tmux, iTerm2, Terminal.app | ✓ | ✓ | iTerm2 / Terminal |
| Linux | ✓ | tmux만 | tmux 창 | ✓ | gnome-terminal, konsole, kitty, alacritty, xterm 등 |
| Windows | ✓ | — | — | ✓ named pipe 사용(실기기 미검증) | Windows Terminal / cmd |

  - macOS 15 이상: 앱을 한 번 열어 차단 메시지를 본 뒤 **시스템 설정 → 개인정보 보호 및 보안**으로 가서 **확인 없이 열기**를 누릅니다.
  - "손상되어 열 수 없음"이 나오면 터미널에서 `xattr -cr /Applications/AgentDesk.app`을 실행한 뒤 다시 엽니다.
  - 앱 내 업데이트로 받은 새 버전도 같은 확인을 다시 거칩니다.
- **Windows**: SmartScreen의 "Windows의 PC 보호" 창에서 **추가 정보 → 실행**을 누릅니다.
- **Linux**: `chmod +x AgentDesk-*.AppImage` 후 실행하거나 `sudo apt install ./agentdesk_*_amd64.deb`로 설치합니다.

### 온보딩

처음 실행하면 6단계 온보딩이 나옵니다. 단계는 소개, 환경 점검, 도크와 핵심 조작, 팀 공유, 연동, 업데이트와 설정이며, 각 단계에서 **건너뛰기**를 누를 수 있습니다. 환경 점검 단계는 에이전트 CLI, 위젯 훅, Orca CLI, 터미널 제어 권한을 확인하고 **정확 감지**를 버튼 하나로 켜게 합니다. 정확 감지는 에이전트 CLI에 훅을 등록해([동작 원리](#동작-원리) 참고) 상태를 추정이 아닌 이벤트로 받게 합니다.

온보딩은 **⚙ 설정 → 기타 → 온보딩 다시 보기**에서 다시 열 수 있습니다. 같은 절에는 **로그인 시 시작**(설치한 앱만)과 **전역 단축키**도 있습니다.

### 업데이트

AgentDesk는 하루에 한 번 GitHub 릴리스를 확인합니다. 새 버전이 있으면 ⚙ 설정의 "업데이트" 행에 표시되고, [받기]를 누르면 이 기기에 맞는 설치 파일(macOS Apple Silicon·Intel DMG, Linux AppImage, Windows 설치 프로그램)을 `~/Downloads`에 내려받아 엽니다. 맞는 파일이 없거나 내려받기에 실패하면 릴리스 페이지를 엽니다. 버전은 `0.2.1`, `0.2.2`처럼 patch 번호를 올립니다.

## 팀 공유

같은 사무실 망에 있는 팀원의 세션을 팀 탭과 픽셀 사무실에서 봅니다.

- 새로 설치한 앱은 이 PC 전용입니다. 서버는 `127.0.0.1`에서만 열리고 자동 발견 비콘도 보내지 않습니다.
- 팀장이 팀 탭에서 **우리 팀 만들기**를 누르면 초대 코드가 클립보드에 복사됩니다. 팀원은 팀 탭의 **초대 코드로 합류**에 그 코드를 붙여 넣습니다. 확인 창을 거친 뒤에만 서버가 `0.0.0.0`으로 열리고 자동 발견이 켜집니다.
- 공유되는 것은 세션 이름, 저장소·워크트리 폴더명, 브랜치, 상태, 현재 도구 이름, 최근 고친 파일의 상대 경로 같은 요약 정보입니다. 프롬프트·응답 본문, 도구 입력값, 전체 경로, 자격 증명은 보내지 않습니다. 보내기 전과 받을 때 비밀 패턴을 마스킹합니다.
- 통신은 HTTP 평문이며, 팀 토큰의 HMAC 서명은 위조와 재전송만 막습니다. 신뢰할 수 있는 사무실 망에서만 켜세요.
- 같은 파일을 동시에 고치는 충돌 알림, 팀원 세션에 메모 남기기, 내 Claude Code 세션을 특정 팀원에게 2시간 동안 위임하기를 지원합니다.

설치, 포트, 연결 문제 해결, 위임의 보안 한계는 [팀 공유 가이드](docs/TEAM-GUIDE.md)에 있습니다.

## Jira 연동

Jira 탭은 두 가지 연결 방식을 씁니다.

- **Atlassian OAuth 2.0(3LO)**: Atlassian 개발자 콘솔에서 직접 만든 OAuth 앱의 Client ID·Secret을 Jira 탭의 **연결 설정**에 넣고 로그인합니다. 콜백 URL은 `http://localhost:47391/callback`입니다. 토큰은 OS 암호화 저장소(safeStorage)로 암호화한 파일에만 저장합니다. 절차는 [Jira 연결 설정](docs/JIRA-SETUP.md)에 있습니다.
- **Orca 폴백**: OAuth로 로그인하지 않았으면 Orca의 Jira 연결(`orca jira …`)로 티켓 목록·상세·댓글을 처리합니다. 칸반 보드는 OAuth에서만 동작합니다.

OAuth로 연결하면 다음을 쓸 수 있습니다.

- **칸반 보드**: 프로젝트를 고르면 보드 설정의 열(읽을 수 없으면 프로젝트 상태)로 카드를 나눠 보여 줍니다. **열 편집**으로 열 순서를 바꾸거나 숨길 수 있고(이 PC에만 저장), 카드를 누르면 드로어에 상세가 열립니다.
- **티켓 배치**: 티켓을 새 Orca 워크트리나 기존 세션에 배치합니다. 지침 템플릿과 최근 지침을 고르고, 보내기 전에 프롬프트를 미리 봅니다. 팀원 세션이 작업 중인 티켓에는 "👤 이름 작업 중"이 붙고, 그 티켓을 배치하려 하면 한 번 더 확인합니다.
- **REPORT → 댓글 초안**: 세션이 `REPORT_START … REPORT_END` 블록으로 보고하면 Jira 댓글 초안을 만들어 보여 줍니다. 빠진 항목이 있으면 경고하고, 확인한 뒤에만 등록합니다. 댓글은 보내기 직전에 마스킹됩니다.
- **티켓별 비용**: 배치한 티켓마다 추정 비용을 합산합니다([한도 소진 예측과 티켓별 비용](#한도-소진-예측과-티켓별-비용) 참고).

<details>
<summary>위젯에서 권한 승인 (Claude Code)</summary>

⚙ 설정 → 감지와 알림 → **위젯에서 권한 승인**을 켜면(기본 꺼짐, 정확 감지가 켜져 있어야 함) Claude Code가 도구 권한을 물을 때 해당 세션 카드에 도구 이름과 입력 요약, **[허용] [거부] [터미널로]** 버튼이 뜹니다. 입력 요약은 Bash는 명령 전체, Write는 내용 앞부분, Edit는 바뀌는 줄, 그 밖의 도구는 입력 JSON 1,000자입니다. 비밀값은 마스킹하고, 보이지 않는 문자와 양방향 제어 문자는 `⟨U+XXXX⟩`로 표시합니다. 헤더에 "승인 대기 N" 배지와 데스크톱 알림도 함께 나옵니다.

- **터미널 질문도 함께 뜹니다. 먼저 답한 쪽이 적용됩니다.** 터미널에서 답하면 위젯 패널은 사라집니다.
- 버튼을 누르기 전에는 아무것도 허용되지 않습니다. "항상 허용" 같은 저장 규칙은 없고, 제안된 규칙이 있어도 "이번만 허용"만 제공합니다. 거부할 때 적은 이유는 Claude에게 전달됩니다.
- 입력이 길어 화면에 다 보이지 않으면 [허용]이 꺼지고 [거부]·[터미널로]만 쓸 수 있습니다. 패널이 새로 뜬 직후 0.8초 동안은 버튼이 눌리지 않습니다.
- **위젯이 꺼져 있으면 기존처럼 터미널에서 묻습니다.** 대기 시간(기본 90초, 설정에서 60/90/180/300초)이 지나거나 [터미널로]를 눌러도 터미널 질문만 남습니다.
- 동작: `~/.claude/settings.json`의 `PermissionRequest`에 동기 훅 `~/.roca/perm-hook.sh`를 추가합니다(기존 로깅 훅과 공존). 훅은 위젯이 연 Unix 소켓 `~/.roca/perm/perm.sock`(디렉터리 0700)으로 요청을 보내고, 위젯이 시작할 때 만든 무작위 토큰(`~/.roca/perm/perm-token`, 0600, 종료 시 삭제)으로 인증합니다. 위젯의 응답은 같은 토큰의 HMAC 서명이 맞을 때만 Claude Code에 전달됩니다. 서버는 훅 이벤트로 본 세션의 요청만 받습니다. 끄면 이 훅만 제거됩니다.
- Claude Code 전용입니다(Codex CLI·Gemini CLI는 해당 없음). macOS·Linux에서는 훅에 `curl`(7.84 이상)과 `openssl`이 필요하며, 없으면 터미널에서 묻습니다. Windows에서는 훅이 작은 Node 스크립트로 동작하고, 실행할 때마다 이름을 새로 정하는 named pipe로 위젯과 통신합니다(실제 Windows 기기에서는 아직 검증하지 않았습니다. 설정의 **훅 연결 상태**에 표시되는 "마지막 훅 연결"로 동작을 확인하세요).

</details>

<details>
<summary>가드레일: 위험 명령 확인 (Claude Code)</summary>

⚙ 설정 → **가드레일**을 켜면(기본 꺼짐, 권한 승인과 별개) Claude Code가 Bash 명령을 실행하거나 파일을 고치기(Edit·Write·MultiEdit·NotebookEdit) 직전에 위험 규칙(`~/.roca/guard.json`)과 맞춰 봅니다. 모드는 끔·경고(기본)·차단입니다.

- **경고**: 걸리면 터미널에서 한 번 더 확인을 받습니다(`--allowedTools`로 허용했거나 bypassPermissions 모드여도 묻습니다). **차단**: 차단 등급 규칙은 거부하고, 이유가 Claude에게 전달됩니다. 경고 등급 규칙은 확인을 받습니다.
- 내장 규칙은 Bash 명령 전체(256KB까지)를, 파일 도구는 **대상 경로만** 봅니다(내용은 보지 않습니다). 사용자 규칙은 명령의 앞 4,000자와 뒤 4,000자만 보므로, 그보다 긴 명령은 (끔 모드가 아니면) 확인을 받습니다. 2MB가 넘는 입력에서 대상 경로를 찾지 못해도 확인을 받습니다. `allowRepos`에 넣은 경로 안에서는 파일 경로 규칙만 건너뜁니다(Bash는 항상 검사합니다).
- **범위 밖**: MCP 도구(`mcp__*`)·WebFetch·Read 등 다른 도구, 그리고 셸 변수로 바꾼 명령(`x=rm; $x -rf /`)이나 스크립트 파일에 써 두고 실행하는 방식은 잡지 못합니다. 샌드박스가 아니라 안전벨트입니다.
- **위젯이 꺼져 있거나 위젯의 응답 대기 2초(훅 자체 제한 3초) 안에 판정이 나오지 않으면 아무것도 막지 않습니다**(fail-open). 훅이 응답을 받기 전에 끊긴 판정은 기록에 "시간 초과로 통과됨"으로 남습니다.
- 사용자 규칙의 정규식은 500자 이하, 한 번에 20ms 제한으로 실행합니다. 시간을 넘긴 차단 등급 규칙은 그 호출에서 확인을 받고, 서로 다른 입력에서 2번 넘기면 "느린 규칙"으로 표시만 합니다(끄는 것은 사용자가 정합니다). 경고 등급 규칙은 2번 넘기면 꺼집니다.
- 기록: `~/.roca/guard-log.jsonl`(0600, 최근 2,000줄, 비밀값 마스킹). 대시보드 "오늘 가드 N"과 세션 카드 "가드 N" 배지에서 볼 수 있습니다.
- 동작: `~/.claude/settings.json`의 `PreToolUse`(matcher `Bash|Edit|Write|MultiEdit|NotebookEdit`)에 동기 훅 `~/.roca/guard-hook.sh`(제한 시간 3초)를 추가하고, 권한 승인과 같은 Unix 소켓·토큰·응답 HMAC 검증을 씁니다. `jq`가 있으면 판정에 필요한 필드만 보냅니다. 팀원의 원격 입력도 같은 규칙 파일로 검사합니다(내장 규칙은 항상 적용됩니다).
- Claude Code 전용입니다. Windows에서는 위젯 승인과 같은 named pipe를 씁니다(실제 Windows 기기에서는 아직 검증하지 않았습니다. 설정의 **훅 연결 상태**에 표시되는 "마지막 훅 연결"로 동작을 확인하세요).

</details>

<details>
<summary>훅 기반 정확 감지</summary>

정확 감지를 켜면 이 컴퓨터에 설치된 모든 에이전트 CLI에 위젯 훅이 추가됩니다: `~/.claude/settings.json`(Claude Code), `~/.gemini/settings.json`(Gemini CLI), `~/.codex/hooks.json`(Codex CLI). 기존 훅은 보존되고 이전 파일은 `~/.roca/`에 백업됩니다. 나중에 설치한 CLI는 다음 위젯 시작 때 자동으로 포함됩니다. 훅 스크립트 `~/.roca/hook.sh`(Windows는 PowerShell `hook.ps1`)는 이벤트를 `~/.roca/events.jsonl`에 한 줄씩 덧붙이고 즉시 종료하며, 위젯이 이 파일을 감시합니다. Claude Code는 훅 설정을 즉시 다시 읽으므로 실행 중인 세션에도 적용됩니다. 끄면 위젯 항목만 제거됩니다.

| 훅 이벤트 (Claude Code / Codex CLI, 괄호 안은 Gemini CLI 이름) | 위젯 상태 |
|---|---|
| `UserPromptSubmit`(`BeforeAgent`), `PreToolUse`(`BeforeTool`, 도구명·대상 기록), `PostToolUse`(`AfterTool`) | 작업 중 |
| `Stop`(`AfterAgent`), `Interrupt` | 대기(10분 후 완료) |
| `PermissionRequest`, `Notification`(`permission_prompt`, `agent_needs_input`, `elicitation_*`, Gemini `ToolPermission`), `PreToolUse(AskUserQuestion)` | 선택 필요 |
| `SubagentStart` / `SubagentStop`, 서브에이전트 안의 `PreToolUse` | 서브에이전트 등장·도구 표시·퇴장 |
| `SessionEnd` | 완료 |

이벤트는 `cwd`와 워크트리 경로로 세션에 매칭됩니다. 훅 데이터가 없는 세션은 화면 판독으로 동작합니다.
</details>

<details>
<summary>화면 기반 판별 (Claude Code)</summary>

화면 판별은 Claude Code TUI의 문구를 기준으로 합니다. 마지막 `❯` 프롬프트 줄을 기준으로 그 위의 첫 의미 있는 줄을 봅니다(들여쓰기된 안내줄과 상태 표시줄은 건너뜁니다).

| 화면 | 상태 |
|---|---|
| `· Working… (1m 14s · ↓ 3.8k tokens)` 같은 스피너 줄, `esc to interrupt` | 작업 중 |
| 스피너 없는 `⏺` 응답 | 대기, 화면이 10분간 그대로면 완료 |
| 10분 이내의 `✻ Worked for 22s · done 2:34 PM` | 대기 |
| 같은 줄이 10분을 넘었거나 다른 날짜 | 완료 |
| `❯` 표시가 붙은 번호 선택지, `Do you want …` | 선택 필요 |
| 프롬프트가 없는 셸 터미널 | Orca 상태 |

시각은 영문·한국어 형식을 모두 해석합니다. 같은 화면에서 서브에이전트 패널(`⏺ main` 아래 `◯ 이름  설명  17s · ↓ 30.5k tokens`)과 상태 표시줄의 컨텍스트 비율도 읽습니다.

## 변경 보기와 리뷰 코멘트

세션 카드를 펼치고 **변경** 탭을 누르면 그 세션 작업 폴더의 git 변경을 봅니다.

- **작업 트리**(HEAD 기준, 커밋하지 않은 변경)와 **브랜치 전체**(`origin/HEAD`·`origin/main`·`origin/master`·`main`·`master` 중 처음 찾은 기본 브랜치와의 merge-base 기준) 중에서 고릅니다. 파일 목록(상태·경로·+/−, 추적하지 않는 파일은 `U`)에서 파일을 누르면 헝크별 diff가 열립니다. 파일 500개, 파일 하나당 300KB·2,000줄을 넘으면 앞부분만 보여 줍니다. 바이너리는 내용 없이 표시하고, diff 줄에 들어 있는 토큰·DB URI 같은 비밀 값은 마스킹합니다.
- 줄 번호를 누르면 그 줄에 코멘트(최대 500자)를 남깁니다. 쌓인 코멘트(최대 20건)는 **세션에 보내기** → 미리보기 확인 후 `[리뷰 코멘트 · N건] 1. 경로:줄 — 내용 … 위 코멘트를 반영하고, 끝나면 REPORT 블록으로 보고해 주세요.` 한 줄로 세션에 입력됩니다(줄바꿈은 공백으로 바뀝니다). 화면을 읽을 수 없거나, 권한·선택 프롬프트에 멈춰 있거나, 입력창에 쓰다 만 글이 있으면 보내지 않습니다(실행 중인 턴에는 보냅니다). 보내지 못한 코멘트는 목록에 남습니다.
- REPORT가 도착한 세션 카드에는 **변경 보기** 배지가 한 번 뜹니다(누르면 변경 탭이 열립니다).
- 변경은 카드를 펼쳤을 때만 읽고(30초 캐시), 파일 diff는 파일을 눌렀을 때만 읽습니다. 위젯은 경로를 직접 받지 않습니다. 메인 프로세스가 세션 ID로 아는 작업 폴더(Orca `worktree ps`, 훅 이벤트의 cwd)만 열고, 파일은 직전 변경 목록에 있던 상대 경로만 허용하며(`..`·절대 경로 거부), 저장소 밖을 가리키는 심볼릭 링크는 읽지 않습니다. 홈 디렉터리 자체가 저장소 루트면 표시하지 않습니다. git은 셸 없이, 외부 diff·textconv·fsmonitor 없이, 인덱스 잠금 없이(`GIT_OPTIONAL_LOCKS=0`) 실행하고 동시에 4개까지만 돌립니다.

## 세션 타임라인

세션 카드를 펼치고 **타임라인** 탭을 누르면 그 세션의 훅 이벤트를 시간축으로 봅니다(정확 감지가 켜져 있어야 합니다).

- 위쪽 요약은 턴 수, 도구 호출·실패 수, 서브에이전트 수, 사용자 대기(응답 완료 → 다음 프롬프트) 합계, 승인 대기(권한 요청 → 다음 도구 진행) 합계, 도구별 호출 수·시간, 가장 오래 걸린 호출 5개를 보여 줍니다.
- 시간축 레인은 3개입니다. 메인 도구 호출(막대 길이는 소요 시간, 색은 도구 종류, 실패는 빨간 테두리), 서브에이전트 구간, 대기(승인 대기 노랑, 사용자 대기 회색)입니다. 마우스를 올리면 시각·도구·요약·소요가 보이고, 누르면 아래 목록의 해당 줄로 이동합니다. **최근 10분 / 1시간 / 전체**로 확대합니다.
- 데이터는 `~/.roca/events.jsonl`을 읽으며 함께 쌓는 메모리 색인(세션당 최근 2,000건, 세션 100개)에서 만듭니다. LLM 호출은 없습니다. 로그 회전으로 사라진 앞부분은 "이전 기록 없음"으로 표시합니다.
- 도구 입력·프롬프트 요약(120자)은 메인 프로세스에서 마스킹한 뒤 위젯으로 보내며, 팀 공유 데이터에는 들어가지 않습니다.

## 한도 소진 예측과 티켓별 비용

- **한도 예측**(Claude Code, Orca 필요): 한도 막대(Orca `account list`의 `rateLimits.claude.session`·`weekly` 사용률과 리셋 시각) 밑에 "이 속도면 약 1시간 40분 뒤 5시간 한도 소진 (리셋 14:30)" 또는 "리셋 전 도달 안 함"을 표시합니다. 최근 30분 샘플로 선형 회귀한 속도이며, 샘플이 적거나 들쭉날쭉하면 "(추정 불확실)"이 붙습니다. 샘플은 최근 30개만 `localStorage`(`roca-usage-samples`)에 둡니다.
- **한도 경고**: 사용률이 80%·95%(설정 → 감지와 알림 → 한도 경고 임계값)를 넘을 때 토스트와 데스크톱 알림을 레벨별로 한 번 띄우고, 창이 리셋되면 다시 알립니다. 막대 색도 같은 값에서 노랑·빨강으로 바뀝니다.
- **티켓별 비용**(Claude Code): Jira에서 배치한 티켓마다 그 작업 폴더의 Claude Code 세션 파일(`~/.claude/projects/*.jsonl`의 `cost-state`) 비용을 배치 시각 이후로 합칩니다. 카드·드로어에는 "비용 $X.XX (세션 N)"으로, 보드 위에는 오늘 배치 비용 합계로, 대시보드 아래에는 티켓별 상위 3개로 보여 줍니다.
- **주의**: 이 비용은 토큰 수 × 정가로 계산한 **추정치**입니다. Pro·Max·Team·Enterprise 구독 요금제에서는 실제 청구액이 아니며, API 청구도 Claude Console 사용량 페이지가 기준입니다. 기존 세션에 배치한 티켓은 그 세션의 배치 이전 비용도 포함합니다.

## 세션 노트 (recall)

`recall/`은 끝난 에이전트 세션마다 짧은 엔지니어링 노트(`파일:줄` 근거가 있는 결론, 결정, 실패한 시도, 남은 의문)를 만들어 로컬 MongoDB에 저장하고, 이후 세션이 같은 분석을 반복하지 않게 합니다. 설치 파일(DMG 등)에는 `recall/`이 들어 있지 않으므로 소스 체크아웃에서 설정합니다. 슬랙 창구(`~/.agentdesk/slack.json`)와 아침 브리핑도 같은 `recall/` 스크립트를 씁니다.

```bash
brew tap mongodb/brew && brew install mongodb-community && brew services start mongodb-community
cd recall && npm install
node cli.mjs install          # Claude Code / Gemini CLI / Codex CLI 에 SessionStart·SessionEnd·PreCompact·프롬프트 훅 + /recall 스킬 등록
node cli.mjs backfill --since 7d   # 선택: 지난 일주일 트랜스크립트 노트 생성
node cli.mjs search "iTerm 세션 매칭"
```

- **SessionEnd**와 **PreCompact**(컨텍스트 압축은 대화의 자연스러운 장 경계이고, 며칠씩 열어 두는 세션을 잡을 수 있는 시점입니다) → 분리된 워커가 트랜스크립트에서 프롬프트와 응답만 뽑고(도구 출력 제외) 비밀 값을 마스킹한 뒤 `claude -p`(Haiku, JSON 스키마 강제)로 노트를 받아 `agentdesk.session_notes`에 git 커밋·워크트리·관련 파일과 함께 저장합니다. 세션당 노트는 하나이며 트리거마다 갱신됩니다.
- **모든 프롬프트**(세션의 첫 메시지 포함) → 프롬프트의 단어로 MongoDB를 검색해 가장 잘 맞는 노트를 최대 3개까지 컨텍스트로 덧붙입니다. 같은 워크트리 노트는 용어 1개, 같은 저장소의 다른 워크트리 노트는 2개 이상 일치해야 합니다. 노트가 의존한 파일이 그 뒤 바뀌었으면 `⚠ N file(s) changed since`로 표시합니다.
- **SessionStart** → 브랜치 이름·수정 중인 파일·최근 커밋의 파일을 검색어로 삼아, 이 워크트리의 노트(또는 편집 중인 파일을 다룬 노트)를 최대 2개 보여 줍니다. 없으면 아무것도 붙이지 않습니다.
- `/recall` 스킬과 `agentdesk-recall search | show | list [--worktree NAME | --all]`로 직접 찾아볼 수 있고, MongoDB Compass(`mongodb://127.0.0.1:27017`, DB `agentdesk`)로 노트를 훑어볼 수 있습니다. `AGENTDESK_MONGO_URL`을 원격으로 바꾸지 않는 한 데이터는 이 컴퓨터를 떠나지 않습니다.

## 문제 해결

- **세션 목록이 비어 있음**: 위젯은 `orca`를 `/usr/local/bin`, `/opt/homebrew/bin`, `/Applications/Orca.app/Contents/Resources/bin`에서 찾습니다. 호출이 실패하면 빨간 배너가 원인을 알려 줍니다. Orca 앱이 실행 중인지, 터미널에서 `orca --version`이 되는지 확인하고, 필요하면 `sudo ln -s /Applications/Orca.app/Contents/Resources/bin/orca /usr/local/bin/orca`를 실행하세요. Orca 없이 쓰려면 정확 감지를 켭니다.
- **Orca 1.4 미만**: 화면 판독과 채팅에 `terminal read --screen`과 `--json`이 필요합니다. 배너가 업데이트를 안내합니다.
- **"터미널 보기"나 메시지 전송이 동작하지 않음**: macOS가 AgentDesk의 iTerm2 / Terminal 제어(자동화 권한)를 한 번 묻습니다. **시스템 설정 → 개인정보 보호 및 보안 → 자동화**에서 허용하세요. 허용하지 않아도 상태는 읽지만 터미널 탭 전환과 입력은 되지 않습니다. Linux는 tmux 안의 세션만 제어할 수 있고, Windows는 터미널 제어를 지원하지 않습니다.
- **상태가 이상해 보임**: 정확 감지를 켜세요. 화면 판독은 Claude Code TUI 문구에 의존하지만 훅은 그렇지 않습니다.
- **팀원 세션이 보이지 않음**: [팀 공유 가이드의 연결 문제 해결](docs/TEAM-GUIDE.md#연결이-안-될-때)을 보세요.
- **Jira 로그인이 안 됨**: [Jira 연결 설정의 문제 해결](docs/JIRA-SETUP.md#문제-해결)을 보세요.
