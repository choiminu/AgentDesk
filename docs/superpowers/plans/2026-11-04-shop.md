# Shop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 🏪 상점 tab in the Skillbook (page and dock panel) that lists plugins, MCP servers and skills from known marketplaces, the MCP registry and Smithery, shows exactly what an install will do, installs with one confirm, and installs from a pasted GitHub link.

**Architecture:** Main-process ES modules in a new `shop/` folder: `catalog.mjs` (fetch + parse + cache), `plan.mjs` (pure: item → install plan), `repo.mjs` (pasted link: validate, shallow clone, detect), `install.mjs` (run a plan). `skillbook/actions.mjs` gains one export for writing an MCP entry safely. `main.mjs` exposes three IPC calls; `widget.html` adds the tab to the existing book.

**Tech Stack:** Electron, Node ≥ 22 built-ins (global `fetch`, `AbortSignal.timeout`), `git` and `claude` CLIs via `execFile`, `node --test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-shop-design.md` (read its "Settled after review" section — it is binding)

## Global Constraints

- No new npm dependencies; network via global `fetch` with `AbortSignal.timeout(10000)`; every fetch failure falls back to the cache (`~/.roca/shop-cache.json`, mode 0600, kept 6 hours) or an empty list with a message — never a crash.
- MCP env values / header values typed by the user: never on a command line, never logged, never returned over IPC, never written anywhere except the one `~/.claude.json` entry. When values are needed, write the entry with `addMcpEntry` (Task 4); use `claude mcp add` only when nothing secret is needed.
- Registry install preference: remote `streamable-http` → remote `sse` → npm package via `npx -y` → pypi via `uvx`; anything else (docker/oci/nuget) or a missing `npx`/`uvx` → plan kind `manual` with the command to copy.
- Pasted links: `https://github.com/<owner>/<repo>` (optionally `/tree/<ref>/<path>`) or `owner/repo` only; public repos; `git clone --depth 1 [--branch <ref>]` into `~/.roca/shop/<owner>-<repo>`; detection order `.claude-plugin/marketplace.json` → `.claude-plugin/plugin.json` → `SKILL.md` folders → `server.json`; several matches → the user picks; README snippets are not parsed.
- Skill install name = SKILL.md `name:` else folder name; existing target → refuse `exists`. "모든 에이전트" → `~/.agents/skills/<name>` plus symlink `~/.claude/skills/<name>` → it.
- Plugin install: `claude plugin marketplace add <source>` when the marketplace is unknown, then `claude plugin install <name>@<marketplace>`; on failure, clone and add as a local-path marketplace and retry; report which route worked.
- "새 버전 있음" only when installed and listed versions are both semver and listed > installed; update only if `claude plugin --help` lists an update command (checked at runtime, cached).
- Smithery is one source module that can be removed by deleting one entry in the sources list.
- Every install needs one confirm in the renderer; no bulk install. Installs are serialized with the Skillbook action queue (`sbQueue` in main).
- UI: inside the existing book (`SB_TABS`, `skillbookRender(root)`), works in the page and the dock panel; user text via `esc()`; Korean strings in `I18N`; `node scripts/csp-hash.mjs --write` after editing the inline script.
- Public repo: no company identifiers in tracked files; test fixtures use made-up names.

## Review Focus

1. Env/header values typed for an MCP install appear in no IPC response, no log line, no argv, no file except `~/.claude.json` (Task 4 test `env values only reach the config entry`, Task 5 test `install result carries no env values`).
2. Network down, timeout or a 5xx / malformed JSON from a source → the other sources and the cache still show; the failing source shows as unavailable (Task 1 test `one failing source keeps the rest`).
3. A hostile pasted link (`https://evil.com/x`, `git@github.com:a/b`, `--upload-pack=x`, `owner/../repo`, a ref starting with `-`) is rejected before any process starts (Task 3 test `only plain GitHub links are accepted`).
4. Installing something whose name already exists (skill folder, MCP entry, plugin installed) refuses with `exists` and changes nothing (Task 4 tests).
5. The registry returns thousands of servers → at most 5 pages × 100 are fetched per refresh, asynchronously (Task 1 test `registry paging is capped`).

### Task 1: Catalog — sources, parsing, cache

**Files:**
- Create: `shop/catalog.mjs`
- Test: `test/shop-catalog.test.mjs`

**Interfaces:**
- Produces:
  - `ShopItem = { id: string, kind: 'plugin'|'mcp'|'skill', name: string, title: string, description: string, source: 'marketplace'|'registry'|'smithery'|'link', marketplace?: string, version?: string, updatedAt?: number, popularity?: number, homepage?: string, repo?: string, registry?: object /* the raw registry server record: packages, remotes */, category?: string }`. `id` = `${source}:${marketplace||''}:${name}`.

### Task 2: Install plans (pure)

**Files:**
- Create: `shop/plan.mjs`
- Test: `test/shop-plan.test.mjs`

**Interfaces:**
- Consumes: `ShopItem` (Task 1).
- Produces: `planInstall(item, { installed, have }) → Plan` where `installed = { plugins: Set<'name@market'>, mcp: Set<name>, skills: Set<name> }`, `have = { npx: boolean, uvx: boolean }`, and
  `Plan = { kind: 'plugin'|'mcp-cli'|'mcp-write'|'skill'|'manual'|'installed', show: string[] /* human-readable lines: commands or files, never values */, needs: string[] /* env/header NAMES the user must fill */, steps?: [{ cmd: 'claude', args: string[] }], entry?: object /* MCP config entry with "${NAME}" placeholders for needs */, oauth?: boolean }`.
  - plugin → `installed` if `name@market` is installed; else steps `['plugin','marketplace','add',<source>]` (only if the marketplace is unknown) + `['plugin','install','name@market']`.
  - mcp (registry record) → follow the preference in Global Constraints; remote → entry `{ type: 'http'|'sse', url, headers? }`; npm → `{ command: 'npx', args: ['-y', '<pkg>@<version>', ...runtimeArgs] }`; pypi → `{ command: 'uvx', args: ['<pkg>==<version>', ...] }`; `needs` from the record's `environmentVariables[].name` / header names marked required or secret; no needs → kind `mcp-cli` with steps `['mcp','add','-s','user', ...]`; needs → kind `mcp-write`; remote with OAuth (no static headers, `auth` hint) → `oauth: true`.
  - registry record with only docker/oci/nuget, or npx/uvx missing → `manual` with `show` = the command to copy.
  - `hasUpdate(installedVersion, listedVersion) → boolean` (semver only).
